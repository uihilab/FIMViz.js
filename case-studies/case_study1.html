Case Study 1 — An observed delineation against a modelled hazard map

Vector-to-raster evaluation of a modelled flood hazard map against a satellite-derived delineation, including the reprojection, and computed to the same numbers in a browser tab and a headless Node run. Protocol: CASE_STUDY_PROTOCOL.md §0 and §1.

The question. Storm Kristin flooded the Sado basin around Ermidas Sado, Portugal in February 2026, and Copernicus EMS delineated the extent from COSMO-SkyMed radar. JRC's European river flood hazard map says where a 1-in-100-year river flood should reach. How much of the delineated flood fell inside that hazard map — and do a browser and a headless run agree on the number?

A secondary question comes free with the data. An EMS delineation product ships an observed extent, mapped from imagery, alongside a modelled extent that extends it where the sensor could not see. The ratio between them is the activation's observability — how much of what was published was actually seen rather than inferred — and it is reported below.

Fig. 1.2Where they disagree

The observed polygons are burned onto the warped hazard grid with rasterize(), then the two binary masks are scored. wet threshold is the modelled depth in metres above which a hazard cell counts as flooded — it is a stated parameter, never a default, and the table reports every value. alignment picks the grid both rasters resample onto. region scopes the metrics to a sub-area with SpatialFilter, because a single basin-wide CSI hides where a map actually fails. opacity fades the overlay.

§Method notes


    
  
  • The warp is the point. The JRC map is EPSG:3035 (ETRS89-LAEA). Nothing else in these
      studies reprojects, so this is the only measurement of warp cost. It runs through
      ds.reproject(), whose GDAL backend is fetched lazily from
      cdn.jsdelivr.net (~38 MB) — a third-party endpoint that has to be declared in any
      zero-backend accounting.
    • 
  
  • Vector reprojection does not exist. reproject() throws for non-raster kinds
      ("geojson/kml/kmz/shp are EPSG:4326 by spec"), so with a projected raster and a 4326 vector the
      only in-engine route is to warp the raster. Here that is also the cheap direction — the raster
      is 11.6 kB and the vector 500 kB — but a host with the ratio reversed has no engine path at
      all.
    • 
  
  • The barrel is not importable under Node. src/package/lib.js does
      export { Loader } from "@googlemaps/js-api-loader", which is CJS and exposes no
      named ESM export, so importing the engine's public entry throws before any user code runs. The
      headless script deep-imports individual modules instead. That is a hard blocker on the parity
      claim, and Case Study 4's headless host inherits it.
    • 
  
  • GDAL is browser-only by packaging, not by capability. The default reprojector resolves
      gdal3.js to that package's browser build, which throws
      sn.readFileSync is not a function under Node. gdal3.node.js ships in
      the same package and initialises in ~160 ms with 128 raster drivers. The headless script
      registers it through Dataset.registerReprojector() — so the seam is what makes
      parity possible, and a conditional export in geo/gdal.js would close the gap.
      io/reprojector.js's header asserts gdal3.js "needs a browser to actually RUN",
      which is not true.
    • 
  
  • The two GDAL builds differ in their API, not just their loader: the browser build's
      open() takes a File, the Node build's takes a filesystem path. One
      reprojector cannot serve both.
    • 
  
  • Rasterization is the slow step. rasterizeFeatures point-tests every pixel
      against every feature, so it scales as pixels × features — measured at roughly 3 s for 73
      polygons onto a 436×401 grid in Node, against 334 ms for the warp it feeds.
    • 
  
  • River hazard against a compound event. EMSR864 is classified as a coastal flood
      activation while its polygons are tagged riverine, and the JRC product models river flooding
      only. Any part of the observed extent driven by storm surge is outside what the hazard map
      represents, so a low containment is not by itself evidence the map is wrong. State this in the
      caption; it is the main threat to the result's interpretation.
    •
