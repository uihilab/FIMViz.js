§Data and models

Flood hazard. WRI's Aqueduct Floods, version 2 (Ward et al., 2020), publishes riverine flood depth in meters on a global 30 arc-second grid, about 0.9 km north–south and 0.8 km east–west at this latitude. The depths come from the GLOFRIS model cascade: the PCR-GLOBWB global hydrological model, with a river and floodplain routing scheme, simulates long runs of discharge and flood volume, and the flood volume for each return period is spread over the terrain as a depth. The historical maps are driven by the EU-WATCH reanalysis for 1960–1999 and are labelled 1980; nine return periods from 2 to 1,000 years are used here. The future maps rerun the same cascade with five CMIP5 global climate models (NorESM1-M, GFDL-ESM2M, HadGEM2-ES, IPSL-CM5A-LR, and MIROC-ESM-CHEM); this study takes RCP8.5 in 2050 at the 100-year return period. Aqueduct applies flood protection in its risk estimates rather than in these depth maps (Society of Actuaries, 2021), and this study applies none, so a cell behind a levee counts as wet wherever the depth map says so.

Population. WorldPop's 2020 population counts at 1 km (CC BY 4.0) redistribute each country's census counts to grid cells with a random-forest model over settlement, land-cover, road, night-light, and other covariates (WorldPop, 2020). The unconstrained variant used here can place people in any land cell, so rural totals are spread thinly rather than concentrated on mapped buildings.

Boundaries. geoBoundaries (Runfola et al., 2020) supplies the Louisiana outline and its 64 parish polygons, which it takes from the US Census Bureau's MAF/TIGER database (public domain).

Preparation. build_case_study10_data.mjs reads each global file with HTTP range requests and keeps only the window over the state plus a 0.1° margin, on the source grid, so nothing is resampled before the page opens it. Cells the source marks as missing become NaN. Table 10.0 lists the fifteen files the page reads.

The nine historical files form one Dataset with a return_period axis: each entry is its own GeoTIFF, and ds.select(rp) fetches only the one on the slider. The hazard class is depth.reclassify([{min: wet, max: 0.5, value: 1}, {min: 0.5, max: 1.5, value: 2}, {min: 1.5, value: 3}]), written as range rules so the recipe below can carry it; cells below the wet threshold match no rule and become transparent.

The five 2050 files form a second Dataset with an unordered, reducible gcm axis. future.reduce("mean") is the ensemble-mean depth, and .combine([today], { op: "difference" }) is the change. The right panel is a ComparisonLayer over the two wet extents, with today as the reference.

An EnsembleAggregationLayer over the five 2050 wet extents counts, per cell, how many models flood it. Cells at 5 are robust to the choice of model; cells at 1 or 2 exist in the ensemble mean only because one or two models put water there.

The population is first masked to the state outline. pop.combine([wetOpen], { op: "min" }) then keeps the population of wet cells, where wetOpen is the depth reclassified to 0 for dry and a large number for wet. min skips an absent input, so each side is made gap-free over the other's footprint first (a sum with a zero raster); otherwise a cell with no population value would pass the large number through, and a populated cell with no depth value would count as wet. zonalStats(units) sums the result per parish, and the choropleth is a vector layer colored by that sum. pop.groupBy(depth, { bins }) gives the same people by hazard class.

§The scene as a recipe

toRecord() writes each product as its sources and its ops, with no pixels. Dataset.fromRecord() rebuilds the chain, which fetches the same files again and recomputes; the table compares the rebuilt totals with the originals.
