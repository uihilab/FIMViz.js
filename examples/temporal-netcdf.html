FIMViz — temporal NetCDF: a time axis you can scrub

The first slice of docs/PACKAGE_ROADMAP.md §8. parseSciwrid(file) scans a multi-dimensional file into a lazy Dataset with a real time axis — one entry per timestep, each an in-file selector rather than a separate download. Scrubbing the slider is layer.setSources([ds.select(coord)]): one slice decodes off the same bytes. The two reduce buttons collapse every timestep via ds.reduce(op), which is sugar over select() + combine() — no bespoke temporal machinery. No GDAL: the decoder resamples onto a geographic bbox, so grids arrive in EPSG:4326 and render directly.
Serve from the repo root (npx serve .) and open /examples/temporal-netcdf.html — ES modules and fetch fail on file://. Run npm run build first (this page loads ../dist/fimviz.js).

1 · Source idle

Three bundled samples, all Hurricane Idalia so the reductions are comparable: NetCDF4 (NLDAS-2, 120 hourly steps, 104×96), Zarr (AORC, 120 steps, 390×390) and GRIB2 (NCEP Stage IV, trimmed to 4 steps, 1121×881). The GRIB2 one pre-fills the extent box, because Stage IV is polar-stereographic and scan() derives no bbox from a curvilinear grid — the same override any such file needs. Any NetCDF4/NetCDF3/GRIB2/Zarr file with a time axis works; the first NetCDF4 decode pulls h5wasm from a CDN.
