A flood-inundation-map engine
that ships no user interface.

Parse GeoTIFF, GeoJSON, shapefiles, NetCDF, GRIB2 or Zarr into a lazy Dataset; clip, mask, reclassify, reproject and reduce it with real spatial operations; render it through Google Maps or Leaflet. Every widget is yours to build — or to take, one at a time, from an opt-in toolkit.

The whole idea

Four calls put a flood raster on a map. Everything else composes from the same three objects.

import { FimViz } from 'fimviz';

// `provider` is required and has no default — the two
// backends differ in credentials *and* in capability,
// so the engine never picks one for you.
const fim = await FimViz.mount('#map', { provider: 'leaflet' });

// Header only. Nothing is decoded, and parsing never
// reprojects: ds.crs is whatever the file itself declares.
const ds = await fim.addDataset(file);

// This is the call that forces the chain — decode,
// colorize, draw — and infers the layer type from ds.kind.
const layer = await fim.addLayer(ds);
layer.fit();

Dataset — a lazy, immutable op chain

A root wraps a source; every operation returns a new node. Nothing is fetched, decoded or warped until a terminal forces it, and the result is memoized per node. That is why an op is cheap, an original is never damaged, and one parse can feed a dozen derivations.

Layer — one rendering of one or more Datasets

Evented, provider-neutral, and it never names an element of yours. It emits; your UI subscribes.

ColorScale — value to colour, and the read-models

One mutable scale with three exclusive modes, from which Legend and Stats are derived — so the legend, the histogram buckets and the pixels on screen can never disagree.

What it is, and what it deliberately isn't

Three decisions you will feel within ten minutes of using it.

Headless, and enforced

No widget markup, no CSS, no panels, and not one window.foo() call into your app. The engine's only outbound channel is an event bus, and a source-scan test fails the build if a core module reaches for the DOM or names a database.

Lazy and immutable

ds.clip(bbox).mask(poly).reclassify(rules) does no work at all. The terminals — grid(), features(), load(), or a Layer rendering it — are what run the chain, once, and memoize it.

It never guesses

Parsing never reprojects. A raster in a CRS the provider cannot draw throws instead of landing in the wrong place. A file with no usable extent throws instead of being placed confidently and wrongly. An unknown palette throws with the list of real ones.

The object model

Small on purpose: two decoded value types, one rendering object, three read-models.

A provider seam, not a Google dependency

Map, vectors and static raster images go through a registered provider — Leaflet and Google ship with it, and a neutral style vocabulary is translated into each SDK's own names. The animated velocity canvas, HAZUS markers and ArcGIS depth tiers remain Google-only.

Registries live on the type they serve

Layer.registerType, ColorScale.registerPalette, Dataset.registerMaterializer, FimViz.registerMapProvider — the library owns the mechanism, your app registers the specifics.
